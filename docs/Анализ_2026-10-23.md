## 2. Как программа ведёт себя на живом стенде
- **Скачивание с YouTube** (`https://www.youtube.com/watch?v=CCPsDy-LH0U`): агентом настоящим кодом получен файл `video.mp4` 3,87 МБ и `metadata.json`. Для этого пришлось добавить в агент JS-среду `deno` и решатель `yt-dlp-ejs` (без них современный YouTube не отдаёт форматы) и терпеливые тайм-ауты. Время 343 с: канал VPN теряет пакеты. [проверено]
- **Kinescope** (две известные ссылки): через VPN 31–76 с и отказы, напрямую 0 с. Запасной переход сработал вживую: VPN не справился → агент перешёл на прямой канал → получил название видео → вернулся на VPN. [проверено]
- **Вывод и доработка:** VPN нужен только для YouTube, поэтому агент теперь выполняет блоки Kinescope напрямую, а YouTube через VPN; при отказе любого канала на время блока переходит на прямой. [проверено тестами; логика маршрутизации по источнику выложена после замеров]
- **Публичная ссылка:** `/login` 200; `/servers`, `/users`, `/settings` ведут на вход; `/docs` 404; `/setup` 403; API 401. [проверено]
- **Стенд:** все контейнеры работают, ошибок в логах нет. База 15 МБ.

## 3. Найдено нового
| Приоритет | Проблема | Статус |
|---|---|---|
| Высокий | **Канал VPN теряет 15–30% соединений** (любой MTU; второй сервер до 50% в провалах). Для YouTube это замедляет загрузку в разы. Причина в самом VPN-сервере, не в приложении. Лечение только сменой VPN. | [проверено] |
| Средний | **Проверка «видео существует» ошибочно считала сетевой сбой «не найдено».** Исправлено: сетевые ошибки теперь `retry_wait`. | исправлено, [проверено тестами] |
| Средний | **Выкладка на NAS в фоновом режиме Docker Compose не пересоздаёт контейнер, если не изменился образ-слой кэша** (случай координатора) — после `up --build` надо проверять, что внутри новый код. | [проверено] |
| Средний | **Покрытие тестами ядра низкое:** планировщик 31%, перенос видео 54%, `router.py` 57%, агент `worker.py` 60%. Итого координатор 65%, агент 71%. | [проверено] |
| Низкий | Пустые опросы агентов раз в секунду создают постоянную нагрузку (~10% процессора координатора). | [проверено] |
| Низкий | Блок не отдаёт результаты, пока не скачается самое долгое видео пачки; нет предела числа повторов блока. | [по коду] |
| Низкий | Токен агента в файле `/etc/vidhive-agent.env` на удалённом сервере с обычными правами; служба от root. | [по коду] |
